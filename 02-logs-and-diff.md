# Анализ логов и сравнение файлов

## О чем этот раздел
Умение читать системные журналы (логи) и находить различия между конфигурациями — главный навык для поиска причин сбоев.

## Ключевые команды и их смысл
*   **`dmesg`** — выводит сообщения ядра Linux (логи оборудования, драйверов, ошибки загрузки). Требует `sudo`, так как содержит чувствительные данные.
*   **`journalctl`** — современная утилита для чтения логов системы (systemd).
    *   `journalctl -u ssh` — показать логи конкретной службы (SSH).
    *   `journalctl -f` — «следить» за логами в реальном времени (аналог `tail -f`).
    *   `journalctl -p err -b` — показать только ошибки с момента последней загрузки.
*   **`grep`** — ищет текст внутри файлов. Незаменим для фильтрации огромных логов.
    *   `grep "ERROR" app.log` — найдет все строки со словом ERROR.
    *   *Флаг `-i`*: игнорировать регистр.
    *   *Флаг `-v`*: инвертировать поиск (показать всё, кроме совпадений).
*   **`diff`** — сравнивает два файла построчно.
    *   `diff config.old config.new` — покажет, что изменилось.
    *   *Флаг `-r`*: рекурсивно сравнить две папки.

## Как это применяется в DevOps
Когда сервер падает, первым делом инженер смотрит `journalctl -p err`, а когда нужно понять, что изменили в конфиге перед сбоем — использует `diff`.
