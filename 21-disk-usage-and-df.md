# Тема: Анализ дискового пространства (df, du)

## TL;DR (Суть в 3 строках)
`df -h` показывает общее свободное место на всех смонтированных дисках, `du -sh` — сколько занимает конкретная папка. Без этого не обходится ни одна отладка упавшего сервера. Переполнение диска — одна из самых частых причин падения сервисов и баз данных.

## Ключевые команды
*   **`df -h`** (Disk Free): Показывает использование дискового пространства в удобном формате (human-readable: KB, MB, GB).
    *   *Флаг `-h`*: автоматически подбирает размерности.
    *   *Флаг `-i`*: показывает использование inode (когда место есть, но файлы не создаются).
*   **`du -sh /path/to/folder`** (Disk Usage): Показывает, сколько реально занимает папка.
    *   *Флаг `-s`*: summary (только итог, без детализации по каждой подпапке).
    *   *Флаг `-h`*: human-readable.
*   **`sudo apt clean`**: Очищает локальный кэш скачанных пакетов (часто освобождает гигабайты).
*   **`ncdu`**: Утилита с интерактивным интерфейсом (нужно установить: `sudo apt install ncdu`), которая позволяет удобно "гулять" по папкам и искать, что именно съело весь диск.

## Применение в DevOps
Если сервер начинает работать со сбоями (например, база данных не может записать лог или транзакцию), первым делом инженер заходит по SSH и запускает `df -h`. Если корневой раздел (`/`) заполнен на 100% — это причина.
Также в CI/CD пайплайнах при сборке Docker-образов важно следить за размерами слоев, чтобы не переполнить диск на билд-сервере.

## Применение в ИБ (Информационная безопасность)
1. **Отказ в обслуживании (DoS)**: Злоумышленник может намеренно заполнить диск (например, через генерацию огромных логов или загрузку файлов), чтобы остановить работу легитимного сервиса. Мониторинг `df -h` — часть защиты от таких атак.
2. **Сокрытие следов (Anti-Forensics)**: Злоумышленники часто прячут вредоносные файлы в неочевидных местах (например, в `/tmp`, `/dev/shm` или в директориях с большим количеством мусора). `du -sh *` помогает аудитору быстро найти аномалии в размерах папок.
3. **Очистка при аудите**: Перед сдачей сервера по требованиям безопасности (PCI DSS, ISO 27001) администраторы очищают кэши (`apt clean`), временные файлы и старые логи, чтобы избежать утечки чувствительных данных из остаточных файлов.
4. **Inode exhaustion**: Бывает, что место на диске есть, но `df -h` показывает 100% из-за заполнения inode (структур, описывающих файлы). `df -i` помогает выявить атаку типа "создание миллионов пустых файлов".
